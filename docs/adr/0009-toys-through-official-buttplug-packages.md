# Toys through the official Buttplug v5 packages

The app talks to toys through the npm packages `buttplug` (5.x client), `buttplug-wasm` (connector) and `buttplug-wasm-blob` (in-app server), replacing a vendored v4 bundle that nobody could rebuild. Toy controls are driven only through the client's own calls (`runOutput` with the toy level as a raw value, `stop`), never raw protocol messages. We send a value rather than a percent because Buttplug rounds a percent up, so float error sent one toy level too many. We still send a command only when the toy level changes, and no more often than the toy's `messageTimingGap` (100 ms if it gives none), counted across all of a toy's controls and its sliders, with `stop` going out at once: flooding a wand with commands made it misbehave, and we haven't confirmed Buttplug filters repeats itself. OSSMs, which don't go through Buttplug, are paced the same way at 100 ms.
